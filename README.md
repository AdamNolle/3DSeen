**3DSeen** is a professional-grade, multi-modal 3D scanning app for iPhone, iPad, and macOS — built to out-feature Polycam end to end. It pushes hardware limits for photogrammetry, LiDAR, and **on-device Gaussian Splatting** to deliver maximum dimensional accuracy and texture fidelity, with a data-dense but Apple-elegant "Studio" interface.

## Why it's different
- **On-device Gaussian Splatting** — capture-to-render radiance fields fully offline (MetalSplatter). Polycam, Luma, and KIRI all push splats to the cloud; 3DSeen never has to.
- **No export paywall, full format parity** — USDZ · USD · OBJ · STL · PLY via ModelIO, free and local.
- **Instrument-grade capture guidance** — live coverage sphere, lighting/distance/motion/sharpness meters, IMU pose, histogram, surface-normal rose, AI scene callouts, thermal pill.
- **Mac offload** — hand the raw scan to your own Apple-silicon Mac over the local network for zero-thermal, max-quality renders.

## Architecture
A Hub-and-Spoke capture architecture with a dual-option compute pipeline, driven by a thread-safe MVVM-C state machine (`ProcessingStateMachine`).

### Capture (iOS)
- **Object** — `ObjectCaptureSession` photogrammetry with interactive AR bounding boxes.
- **Space** — Apple `RoomPlan` → parametric USDZ.
- **Landscape** — ARKit VIO world tracking (no LiDAR) with automatic frame capture for outdoor scenes.
- **Auto-Pilot** — Vision scene classification recommends the optimal mode from the live feed.

### Compute
- **On-device** — RealityKit `PhotogrammetrySession`, with `ProcessInfo.thermalState` monitoring + auto-pause.
- **Mac offload** — `MultipeerConnectivity` streams the scan to the macOS app, which unzips → renders on the Neural Engine/GPU and reports live pipeline progress.

### UI — "Studio" design system
A native SwiftUI design system (`Sources/Shared/DesignSystem/`) — warm-paper light + refined dark theme, single cobalt accent, adaptive Liquid Glass — across 10 screens: Library · Mode · Briefing · Capture · Detail · Review · Compute · Viewer · Export · Settings.

## Requirements
- **iOS / iPadOS** 17.0+ (LiDAR recommended for Space/Object).
- **macOS** 14.0+ (Apple silicon recommended).
- **Xcode** 16.0+ (Xcode 26 requires the Metal Toolchain component — see below).

## Setup
The Xcode project is generated by [XcodeGen](https://github.com/yonatankra/xcodegen) (`project.yml`), so it never lives as a merge-conflict magnet.

```bash
brew install xcodegen
xcodegen generate
open 3DSeen.xcodeproj          # build 3DSeen-iOS or 3DSeen-macOS
```

> **Xcode 26 note:** the Gaussian-splat renderer (MetalSplatter) compiles `.metal` shaders. If a build fails with *"missing Metal Toolchain"*, run once:
> ```bash
> xcodebuild -downloadComponent MetalToolchain
> ```

## Develop

```bash
# Lint (matches CI — must pass clean)
swiftlint lint --strict

# Unit tests
xcodebuild test -scheme 3DSeen-iOS   -destination 'platform=iOS Simulator,name=iPhone 16'
xcodebuild test -scheme 3DSeen-macOS -destination 'platform=macOS'
```

- **Linting:** `.swiftlint.yml` (strict in CI).
- **Tests:** XCTest suites in `Tests/iOS` and `Tests/macOS` covering the state machine, exporter, Auto-Pilot classification, PBR estimation, splat matrices, and the compute pipeline.
- **CI/CD:** `.github/workflows/ci.yml` runs SwiftLint + builds/tests both targets on every push & PR; `release.yml` builds unsigned artifacts on `v*` tags.

## Project layout
```

  macOS/             # Studio compute dashboard + library, ComputeCoordinator
Tests/               # iOS + macOS unit tests
.github/workflows/   # CI + release
```
